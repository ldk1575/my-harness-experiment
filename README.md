# my-harness-experiment

기준 도구: Claude Code 2.1.296 · 모델 `claude-sonnet-5-5` · 다룬 하네스 기능: **미니멀**
(모두의연구소 AI 에이전트 2기, 「에이전트 하네스 톺아보기」 11강 과제)

## 배경 — 왜 이 실험을 했나

수업과 개인 작업을 하면서 Claude Code에 플러그인을 하나씩 들이다 보니, 지금은 모든 세션에 플러그인 24개 · 스킬 220개 · MCP 서버 22개 · SessionStart 훅 8개와 전역 CLAUDE.md 규칙이 실린다. 세션이 느리고, 작은 일에도 절차가 붙는다는 불편을 느꼈다. 한 줄짜리 질문으로 재 보니 이 전역 계층을 끈 조건보다 시간은 약 1.9배, 입력 토큰은 약 2.9배였다([probe/](probe/)).

그래서 확인하고 싶었던 것은 하나다. **그 비용을 치르고 얻는 것(검증 규칙, 스킬)이 실제 작업 품질을 올리는가?**

## 가설

사용자 전역 계층(플러그인 · 스킬 · MCP · 훅 · 사용자 설정)을 끄고 실행하면, 작은 코딩 작업 3개에서 테스트 통과율은 떨어지지 않으면서 작업당 총 입력 토큰과 소요 시간이 줄어든다.

## 실험 설계

| 구분 | 내용 |
| :--- | :--- |
| 고정 | Claude Code 2.1.296, `claude-sonnet-5-5`, fixture 3작업(노드 예시의 parse-log · refactor-util · fix-failing), 같은 요청 문장, 같은 권한 플래그, 실행마다 새 복사본 · 새 세션 |
| 조작 (하나) | A = 평소 실행 / B = `--setting-sources project --strict-mcp-config --disable-slash-commands` |
| 측정 (이중) | 품질: 공개 테스트 + **숨긴 테스트**(모델에게 안 보여 줌) 통과 / 비용: 총 입력 토큰, 소요 시간, 턴, 수정 횟수, 권한 거부 |
| 반복 | 3작업 × 2조건 × 3회 = 18회, A · B 순서 교대 |
| 사전 판정식 | 세 작업 모두 B 통과 횟수 ≥ A, **그리고** 2개 이상 작업에서 B의 토큰 · 시간 중앙값이 둘 다 A보다 작으면 지지. 그 외 기각 |

1~3절(가설 · 설계 · 판정식)은 실행 전에 커밋했다(`bd31d2c`).

## 결과 — **지지**

| 작업 | 통과 A / B | 총 입력 토큰 중앙값 A / B | 소요 시간 중앙값 A / B |
| :--- | :--- | :--- | :--- |
| parse-log | 3/3 · 3/3 | 870,281 / 164,598 (5.3배) | 99.1초 / 27.7초 |
| refactor-util | 3/3 · 3/3 | 189,258 / 96,545 (2.0배) | 43.8초 / 21.3초 |
| fix-failing | 3/3 · 3/3 | 265,778 / 197,658 (1.3배) | 56.9초 / 19.8초 |

18회 모두 숨긴 테스트까지 통과했고, 비용은 세 작업 모두 B가 적었다. API 환산 비용 합계는 A 2.07달러, B 0.57달러다.

**비용 차이는 두 갈래에서 나왔다.**
1. **고정 비용** — 작업과 상관없이 첫 요청 입력이 6.2만 대 3.2만 토큰, 훅 등 API 밖 시간이 11.8~14.5초 대 2.6~4.1초였다. 이것이 7강 미니멀의 문제다.
2. **전역 규칙** — parse-log에서는 A가 3회 모두 `parse.py` 보다 `PRD.md` 를 먼저 썼다. 요청의 "작성해줘"에 전역 CLAUDE.md의 "PRD 먼저" 규칙이 걸렸다. 도구 수가 아니라 **규칙의 적용 범위** 문제다.

**한계** — 작업이 쉬워 18회 모두 통과했다(천장 효과). "켜서 얻는 품질 이득이 이 규모에서는 관찰되지 않았다"까지만 말할 수 있다. 조작이 묶음이라 어느 항목이 비용을 만드는지는 나누지 못했다.

## 다시 검토할 조건

Claude Code 버전 · 모델 · 플러그인 구성 · 전역 CLAUDE.md가 바뀌거나, 작업이 여러 파일 단위로 커지면 다시 확인한다. 다음 실험은 항목을 **하나씩 끄고**, PRD 규칙의 적용 범위를 좁혀 보고, 더 어려운 작업으로 천장 효과를 벗어나는 것이다([experiment-01.md 8절](experiment-01.md#8-다음-실험-계획)).
